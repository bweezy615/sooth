## What Sooth is, and why that constrains you

Sooth is a line-shopping and betting-research site whose entire positioning is
**"the arithmetic is the product."** It publishes its own model's losing record.
It sells nothing, takes no wagers, and makes no win-rate claim.

That makes a wrong number on this site worse than a broken feature. A site that
argues its numbers are reproducible, and then displays a number nobody can
reproduce, has destroyed the only thing it was selling. Weigh every change that
way: correctness and honesty first, features second.

Two models run per game: `independent` (elo+epa-v1, never sees the line — our
actual opinion) and `consensus` (elo+epa+market-v1, mostly reproduces the market).
Both are sealed under the same Merkle commitment before kickoff. ATS breakeven at
-110 is 0.5238.

## Hard rules — not preferences

1. **No published number is ever hand-typed.** Every figure on the site comes from
   `scripts/published_figures.py` → `site/content/_figures.json`. If you need a
   number, generate it. If you find a hand-typed one, either wire it to the
   generator or add a test asserting it against `_figures.json`.
2. **Zero win-rate or performance claims** anywhere in copy. Backtest tables on
   /methodology only, generated by the script, always shipped with the confidence
   interval and every losing season.
3. **Never re-seal `2026-W01-nfl`.** Its Merkle root was anchored to a public
   GitHub commit on 2026-08-06 and is the flagship /verify walkthrough. New fields
   appear from W02 forward. If re-sealing ever looks necessary, stop and ask.
4. **Never `--force` push, never push a red gate, never push to any branch but
   `main`** (which is what this repo uses). No exceptions while unattended.
5. **Never bypass the paywall/auth model or invent a payload.** `api/picks.js`
   fails closed by design: a slate that cannot be decrypted is reported
   unavailable, never reconstructed.

## How to work

Follow the repo's standing process (`~/.claude/CLAUDE.md`): understand the code
before changing it, write the plan down in `docs/plans/`, audit it against the
codebase, then execute phase by phase, verifying each phase before the next.

- **Fix roots, not symptoms.** If a fix is a workaround, log it as visible debt in
  the commit message and the plan doc. Never silently.
- **Simplicity first.** Minimum code that solves the problem. No speculative
  features, no premature abstractions, no touching adjacent code to "improve" it.
- **Leave a check behind.** Any non-trivial logic gets one runnable test that
  fails if the logic breaks. This matters here more than most places — see below.
- **Browser-verify anything a user can see** before committing. `preview_start`
  with a static server on `site/public`, check the rendered result and the console,
  then stop the server and clean up any config you added outside the repo.
- Commit messages explain *why*, name the root cause, and state what you actually
  verified — never what you assume.

## Lessons this repo has already paid for

Read these as failure modes to actively hunt, not history.

- **A comment is not a check.** `scripts/build_site.py` carried a "⚠ DRIFT WARNING"
  telling readers to diff before running. It sat there five days while all four
  pages it generates drifted, and a rebuild would have republished superseded
  figures and deleted a live section. The fix was `tests/test_build_site.py`. When
  you are tempted to write a warning comment, write a test instead.
- **Anything kept in sync by hand goes stale.** `site/public/data/figures.json` was
  a manual copy of `_figures.json`. It sat 19 days and 344 values stale, so
  /record and /trust quoted a different ATS record than /methodology did. If two
  artifacts must agree, one command writes both and a test holds them together.
- **Check the payload, not just the HTML.** The above was missed precisely because
  a sweep looked at rendered pages and not the JSON `desk.js` fetches at runtime.
  When a figure changes, grep the data payloads too.
- **Changing the model changes the copy.** The edge-threshold change made /picks'
  headline ("No selection rule") and the /record note ("no edge threshold") into
  false statements. After any engine change, re-read the prose that describes the
  engine. A stale claim on this site is a lie, not a typo.
- **`git checkout --` on an uncommitted file destroys the work.** Commit or stash
  before reverting anything experimental.
- **Don't hand-edit generated files.** `site/public/{methodology,verify,
  disclaimers,ledger}.html` come from `build_site.py`. Edit `site/content/*.md` or
  the generator, then rebuild.

## Current backlog

Work in this order. Plan each one before coding.

1. **The two-"Ledger" nav collision.** `/trust` is titled `Sooth — Ledger` and the
   nav's LEDGER link points at it; `ledger.html` is titled `Ledger — Sooth` and is
   only reachable from `index`, `methodology` and `record`. Two pages, one name,
   and the real ledger is unreachable from the nav. Decide what each page is
   actually for and name them accordingly — this is a trust surface, so the fix is
   about clarity for a skeptical reader, not just a link.
2. **`site/public/data/research.json` is 1.5 MB**, roughly 3× the next-largest
   payload, and every visitor to that page downloads it. Find out what is in it,
   whether the page needs all of it, and shrink it — pagination, splitting, or
   dropping fields the UI never reads.
3. **`methodology.md`'s figures are hand-typed** (its prose and tables both), which
   violates hard rule 1. They are currently correct and pinned by
   `tests/test_figures_published.py` only for /disclaimers. Wire /methodology's
   numbers to `_figures.json` — placeholders substituted at build time — so they
   cannot drift again.
4. **W02 dry run.** W01 kicks off 2026-09-09; W02 seals the Wednesday after and is
   the first slate to carry the new `ats` fields and render the SPREAD PLAY column
   on /picks. Before it seals for real, build a slate into a throwaway root (see
   the pattern in the scratchpad `slate_probe.py` referenced in
   `docs/plans/pick-engine-selectivity.md`) and confirm the payload, the ranking
   and the page render are right. **Do not seal anything for real.**

After the backlog, keep going: audit the site for further correctness and honesty
defects and fix them. Prioritise by the standard above — a number that disagrees
with itself, or copy that claims something untrue, outranks any feature. Prefer
finding real defects over inventing work; if you genuinely run out, say so rather
than manufacturing changes.

## Reporting

Keep `docs/plans/` current — that is the handoff. At the end of a session give
Branden a short plain-language report: what shipped, what you verified (the actual
commands and their results), what you found and did not fix, and what needs a
decision from him. Be honest about failures; a test you did not run is not a test
that passed.

Stop and ask rather than guessing when: a change would alter a sealed commitment,
retire a published claim, cost money, or touch how the site describes its own
accuracy in a way you cannot verify from `_figures.json`.
