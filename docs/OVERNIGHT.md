# Overnight work plan

Written 2026-08-03. Work runs unattended while the user sleeps. The point of
this document is to make that safe: an agent working alone on a public repo
with a live API key and a public website can do real damage, and the failure
mode is not "does nothing" - it is "confidently ships something wrong."

---

## Guardrails — these are hard limits, not preferences

**1. Never publish a performance claim that was not produced by a run in this
repo.** Every number on the website must be traceable to `engine/backtest.py`,
`engine/models/ensemble.py`, or `engine/closing.py`. If a number cannot be
regenerated by a command, it does not go on the site. This is the FTC
substantiation posture and it is the whole product.

**2. Never mark a sport, market, or model "Live" autonomously.** Promotion
from *In calibration* to *Live* is a judgement call with legal weight. Propose
it in the morning report; do not do it.

**3. Never spend more than 500 Odds API credits in one night.** 7,580 remain
and they do not renew until the billing month rolls. The live capture cron
needs headroom. A backfill that exhausts credits cannot be undone.

**4. Never rewrite or delete a committed slate, a reveal file, or anything
under `data/capture/`.** These are the evidence. Append only. If a commitment
looks wrong, write a new one and record why - never edit history.

**5. Never push anything that names a competitor.** See
`docs/competitor-notes.local.md` (gitignored) for why.

**6. Never commit a secret.** `.env` is gitignored. Verify before every push
with the WORD-BOUNDARY form:

```bash
git diff --staged --name-only | grep -qx '.env' && echo "LEAK: .env staged"
git diff --staged | grep -oE '\b[0-9a-f]{32}\b' | sort -u   # empty == clean
```

The boundaries matter. `[0-9a-f]{32}` without them matches a substring of
every 64-char SHA-256 Merkle hash we publish, so it fires on literally every
commit. A check that always cries wolf trains you to ignore it, which is worse
than having no check at all. This exact mistake happened on the first
overnight pass.

**7. Work on `overnight/<topic>` branches, not `main`.** `main` deploys to
production on push. Merge in the morning after review.

**8. If a task requires a decision the user has not already made, stop and
write it into the morning report.** Do not guess. Examples: brand copy
changes, pricing, what goes on the front page, whether to promote a market.

## Priority queue

Work top to bottom. Each item states what "done" means, because a task without
a verification step is a task that will be reported complete while broken.

### P0 — Commitment versioning *(integrity gap, found tonight)*

Re-sealing Week 1 overwrote root `d081c00f…` with `4136512c…`. That was
legitimate - kickoff is 37 days away and predictions may change until games
start - but the scheme overwrote it *silently*. A reader who recorded the old
root would find it simply gone, which is indistinguishable from tampering.

Fix: version commitments. `<slate>.commitment.v1.json`, `v2`, … each retained
forever, with the ledger showing the full history and marking which one was
final at kickoff. Add `supersedes` pointing at the prior root.

**Done when:** re-running `weekly.py` twice produces two retained commitment
files, `/ledger` shows both with timestamps, and `verify_slate()` validates
against the final one while still resolving superseded roots.

### P1 — Regenerate every published figure from the validated closes

The site currently cites the nflverse-based backtest (2,750 games, 49.65%
ATS). We now have 854 games graded against real 17-book closes. Both are
honest; the second is better evidenced and has a smaller sample.

Do **not** silently swap one for the other. Publish both, with sample sizes,
exactly as we did for the two models.

**Done when:** `methodology.md` carries both tables with `n` stated, the
homepage stat cards cite the validated figures, and every number is
reproducible from a named command.

### P2 — Grading pipeline

Nothing yet grades a revealed slate against results. Needed before Week 1
settles or the ledger is a promise rather than a record.

**Done when:** `engine/grade.py` takes a settled slate, computes per-model
record, Brier, and CLV against `own_capture` / `oddsapi_historical_close`
rows only, and writes a graded artefact the ledger renders. Test it on a
2025 slate replayed from the backfill.

### P3 — Tighten capture cadence near kickoff

Every 3 hours is fine in August. In-season the last hour before kickoff is
where the closing line actually forms. Add a schedule that polls more
frequently inside T-90 minutes.

**Done when:** the workflow polls at least every 15 minutes inside that
window, and credit burn is projected for a full week and stays inside budget.

### P4 — Second sport behind the same interface

NBA or EPL, per `multisport-data-plan.md` - both have better free closing-line
history than NFL. Implement `SportAdapter` only. If it needs changes to the
engine, that is a finding worth reporting, not a licence to fork the code.

**Done when:** the adapter loads history, results, and lines, and a
walk-forward backtest runs end to end. Ships **In calibration**, never Live.

### P5 — Tests

There are none. The leakage guard, `devig`, `american_to_prob`/`prob_to_american`
round-tripping, Merkle proofs, and the closing-window filter all deserve them.

**Done when:** `pytest` runs green and covers those five.

## Morning report

Write `docs/reports/<date>-overnight.md` containing: what was completed with
its verification output, what was attempted and abandoned and why, every
decision deferred to the user, credits spent, and the exact commands to
reproduce any number produced. Lead with anything that contradicts a previous
finding - a result that overturns earlier work is the most valuable thing in
the report, not the most embarrassing.
