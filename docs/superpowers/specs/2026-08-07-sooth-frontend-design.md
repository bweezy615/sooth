# Sooth — new frontend design & build plan

Date: 2026-08-07
Status: approved (design), ready to build
Owner: Branden (bweezy615)

## Goal

Replace the current single-file dark indigo/violet landing with a new,
"pro terminal" frontend: a full multi-screen static app whose star is the daily
odds **Board**. Identity-first, board-forward.

## Frozen constraints (from PRODUCT.md + HANDOFF.md — do not violate)

- **Static files only.** No backend server, no database, no build step. Every
  page is HTML that fetches static JSON from `/data`. The site is a *reader*.
- **No wagers, no funds, ever.** Odds analysis tool, not a sportsbook.
- **Banned words anywhere in UI:** guaranteed, lock, risk-free, insider,
  sure thing.
- **No performance claim** that isn't regenerated by
  `scripts/published_figures.py`. Numbers come from the JSON, not hardcoded.
- **Confidence caps at 0.85** (already applied in data — never re-derive).
- **18+ and responsible-gambling helpline 1-800-522-4700 on every page.**
- Always **timestamp the board** ("last read …") — prices move constantly.
- Audience = sharp bettors. **Density over persuasion. Information per pixel.**
  No tutorial tone, no hand-holding.

## Visual identity — "the terminal"

- **Near-black** ground (~#0A0B0F), high-contrast off-white ink, dim/muted grays
  for secondary text.
- **Monospace for every number** (JetBrains Mono, already loaded), tabular,
  right-aligned in tables. A compact grotesk (Archivo, already loaded) for labels
  and prose.
- **One accent: terminal green** (~#3DDC84 / reuse `--pos` #4ADE80) for gains and
  positive; red (`--neg` #F87171) for negative. **Remove the indigo/violet
  gradient entirely** — that was the templated-SaaS tell.
- Terminal chrome: a status bar (live clock, "N books", "updated 41s ago"),
  hairline separators, dense data grid, no decorative blobs or big gradients.
- Accessibility: focus-visible outlines, `prefers-reduced-motion`, skip link,
  aria on tabs/tables, contrast AA.

## Screens

All static HTML under `site/public/`, sharing `assets/sooth.css` + a shared
header/footer.

1. **`board.html` — the daily tool (the star).** Full odds board from
   `board.json`: every side, best price + which book, fair line, gain (+Δ pts).
   Sport tabs (NFL/MLB/NHL/NBA/UFC), sort (gain / matchup / time), filter by
   sport & market, live "last read" timestamp. Graceful empty state when no
   games are in the window.
2. **`index.html` — home / landing.** Board-forward: leads with a live board
   teaser (top edges) + the honest-record strip, primary CTA = **subscribe**
   (Stripe Payment Link from the subscribe-flow agent's snippet). Sells by
   showing the tool, not by hype.
3. **`record.html` — honest performance.** 49.5% ATS, break-even 52.38%, Brier,
   calibration, weekly variance, "0 graded picks yet." Reads `_figures.json` /
   `backtest_curve.json`. Credibility page, not a pitch. "We publish the losses."
4. **Reskin existing content pages** into the terminal identity (do not rebuild):
   `verify.html`, `ledger.html`, `methodology.html`, `disclaimers.html`.
5. **Subscribe / account.** Subscribe CTA + Stripe customer-portal link.
   From `docs/subscribe-plan.md` + `site/public/_partials/subscribe.html`
   (Stripe Payment Links, placeholders the user fills in). Client-side gating is
   NOT real access control — gating decision (soft / one serverless fn / none)
   is deferred to the user per the subscribe plan.

## Data the frontend consumes (all static JSON, already produced)

- `board.json` — the full board (best/fair/gain per side). Board + home.
- `best_lines.json` — best available lines. Board/home as needed.
- `2026-W01-nfl.json` — weekly sealed slate (models, picks, caps).
- `_figures.json`, `backtest_curve.json` — record page.
- `*.commitment.json` / `*.reveal.json` — verify page (any version, per §4.2).

Contracts are documented in HANDOFF §4. Note asymmetries: `prob` is the pick's
prob (already capped); `market_prob` is the home team's de-vigged prob.

## Architecture / shared code

- **Vanilla HTML/CSS/JS, no framework, no build** (matches HANDOFF §3).
- One shared `site/public/assets/sooth.css` (design tokens + terminal
  components: status bar, data grid, tabs, chips, cards).
- Shared header/footer: a tiny `assets/shell.js` that injects the common nav +
  legal footer (helpline, 18+, disclaimers) so every page stays compliant
  without duplicated markup drift. (ponytail: one small include beats a build
  step or copy-paste across 7 pages.)
- Escape all data rendered into the DOM (existing `esc()` pattern).

## Build order (phases — build → preview in browser → commit each)

- **Phase 0 — Design system.** `assets/sooth.css` + `assets/shell.js`
  (header/footer). A tiny `_styleguide.html` to eyeball tokens/components.
- **Phase 1 — Board.** `board.html`, full tool, reads `board.json`. The thing
  people pay for → first.
- **Phase 2 — Home.** `index.html` board-forward + subscribe flow wired in
  (from the subscribe agent's snippet + placeholders).
- **Phase 3 — Record + reskin** verify/ledger/methodology/disclaimers.
- **Phase 4 — Account/subscribe page, responsive, a11y, final ux-designer
  review pass.**

Each phase: eyeball in a real browser (visual-before-commit) before committing.

## Testing / verification

- Preview locally: `cd site/public && python -m http.server 4173`.
- Every phase browser-checked (desktop + mobile width) before commit.
- Compliance checklist per page: banned words absent; helpline + 18+ present;
  no hardcoded performance numbers; board timestamped.

## Out of scope (YAGNI)

- No native app (Apple/Play) — HANDOFF §8.5, decide later.
- No real backend/auth — gating stays soft per subscribe plan until user picks.
- No new sports beyond what the engine emits (NBA handled by its own agent).
