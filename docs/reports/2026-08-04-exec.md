### Built

`engine/alerts.py`. Two detectors, deliberately separate because they are not
the same signal:

- **drift** — one book's own price moved between our observations. That is the
  book changing its mind.
- **divergence** — a book's current price sits away from the cross-book median.
  That is the one that pays immediately.

Both measured in points of implied probability, never raw American odds, which
are non-linear and discontinuous across ±100. Provenance-gated to `own_capture`
exactly like CLV: `espn_open` is someone else's claim about a price we never
watched.

Those two alerts are the two sides of one coherent move: DraftKings shifted the

### Built

`engine/lines.py` now appends every individual book quote to
`data/capture/<sport>/<date>.jsonl` with provenance `own_capture`, append-only,
one file per sport per UTC day. This unlocks divergence alerts and multi-book
CLV in one change.

### Bug found, and it was dangerous

Writing the rows immediately exposed a name collision:

```
Draft Kings   espn      nfl   1716
DraftKings    espn      nfl   3056
DraftKings    oddsapi   mlb     30
```

**ESPN returns both spellings for the same operator.** Left alone, one book is
counted as two. Divergence requires 3+ books before it will claim a consensus,
so a split identity can push a 2-book market over that threshold and fire an
alert against a consensus that does not exist.

This is a **pre-existing bug in our ESPN capture**, not one this change
introduced. It was invisible while capture was single-book, and would have
started producing false alerts the moment divergence went live.

Fixed with `canonical_book()` in `engine/schema.py`, applied at write time in
both writers:

```
DraftKings         -> DraftKings
Draft Kings        -> DraftKings
williamhill_us     -> Caesars
BetOnline.ag       -> BetOnline
barstool           -> ESPN BET
```

history without rewriting evidence:

### The pattern this makes six

Six verification steps in this project have now reported something false or
incomplete. This one is the most instructive: the production run genuinely
succeeded, the tests genuinely passed, and the feature was genuinely still
broken. **A green check on the thing you changed says nothing about the data
that was already there.**
